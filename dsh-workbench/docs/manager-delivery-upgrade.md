# 管家沟通与交付升级（1.14.0）

## 使用方式

1. 管家消息分为结果摘要、短段落、要点、待回答问题、折叠说明和成果入口。旧对话仍可阅读；新消息使用经过校验的结构。
2. 可以直接选择问题选项，也可以填写回答。回答会持久保存；同阶段相同问题不会重复显示为新问题。回答不会批准阶段或启动编码。
3. 在「我的成果 → 交付模板」选择并确认模板，点击「检查内容与来源」。有多个同名来源时，可以为章节选择来源，修改后重新检查。
4. 缺少内容时，补充对应阶段文档、重新审阅并确认，再重新检查。也可以明确选择「保留缺口，生成标记草稿」。草稿文件名、正文和来源记录均有标记。
5. 检查通过后生成正式交付件；每次生成保存为独立版本，可下载版本与来源记录。格式异常不会把原始 JSON 或工具标记直接展示为正常管家回复。

旧版已确认模板需要重新确认一次，以绑定模板内容的指纹。文档确认记录不受此迁移影响。

## 内容与来源

交付输入取自当前确认凭据所对应的不可变快照，并校验 SHA-256、需求轮次、阶段与当前版本。文档确认后发生修改，会要求重新确认。尚未确认的知识节点不会代替正式来源填充内容。

正式生成和预检查使用同一条校验路径，服务端会再次检查。章节同名或模糊匹配到多个来源时不再静默选取第一项。来源选择仅选择已确认材料；不会自动编写、补全或确认缺失的业务事实。

上传 Word 模板的未填占位符也计入缺口。Word 占位符仍以整段 `{{章节名}}` / `{{正文}}` 为主；复杂嵌套表格、页眉页脚中的占位符不在本轮增强范围内。缺少作者、实验数据、截图等材料时，应先补充到正式文档后确认，本轮没有新增自动检索或虚构素材功能。

输出按生成时间和随机标识保存，先在临时目录生成，完成后发布。记录包括来源确认 ID、文档修订和哈希、模板内容指纹、章节映射、草稿/正式状态、内容缺口、导出警告及输出文件哈希。

## PDF 与 PPTX

- PDF 优先通过已检测到的 LibreOffice 转换 Word。转换不可用或失败时，使用 PDFKit 在本机生成 A4 内容版 PDF，不发送文档到第三方转换服务。
- 本地 PDF 保留文本、标题、列表、代码内容和页码。为保证分页可读，表格转为带列名的逐行记录；不复刻上传 Word 模板的复杂版式，会显示相应提醒。
- 服务器需安装中文字体。可设置 `DSH_PDF_FONT=/绝对路径/中文字体.ttf`；TTC 字体可配合 `DSH_PDF_FONT_FAMILY` 指定 PostScript 字体名。自动检测 macOS Arial Unicode、Linux UMing / Noto CJK。缺字体时明确提示，不生成乱码 PDF；其他格式仍保留。
- 答辩 / 概念演示等演示类交付额外生成原生 PPTX，包含可编辑文本、形状和表格。长文本分页，宽表分组，保留原有 HTML 打印稿。
- PPTX 当前使用内置基础版式，不支持导入任意 PPTX 模板、复杂图表和动画。打开端仍需具备中文字体。没有新增模型绘图或素材搜索；相关素材缺口继续如实列出。

## 安装与验证

在插件目录运行 `npm ci` 安装锁定依赖，然后重启 DSH Host 并刷新页面。新增运行模块均已加入包文件清单。

执行 `npm run check` 与 `npm test`。回归覆盖结构化协议、问题回答持久化与去重、异常回复回退、快照完整性、歧义映射、正式交付拦截、显式草稿、正式交付、版本与输出哈希、PDF 字体和 PPTX 原生对象。

本轮浏览器验证使用隔离项目，导出样张使用虚构内容；未调用真实 DeepSeek 服务或更改用户业务项目。
