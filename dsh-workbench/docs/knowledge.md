# 项目知识与阶段上下文（1.6.0）

## 使用入口

主工作区选择「项目知识」。

- **知识与关联**：搜索编号、标题、正文和已登记资料的全文；按类型/状态筛选；查看来源位置、哈希、关联链和追溯缺口。
- **本次上下文**：选用/排除来源、设置字符预算、预览正文与节选记录、查看上次实际构建的清单。
- **新增知识**：补充文档没有表达的约束、决策、验收或证据；保存时明确选择草稿/已确认/已废弃。
- **打开来源文档**：回到对应阶段的正式文档，继续使用第二批的差异审阅和段落评论。

## 数据归属

```text
.dsh/workbench/changes/<boardId>/
├── documents/                   # 正式文档：文档提取条目的事实来源
├── knowledge.json               # 手工条目、手工关联、参考资料、废弃标记和阶段选择
└── contexts/
    ├── <uuid>.json              # 构建时的不可变上下文记录
    └── latest-<stage>.json      # 最近记录的指针
```

文档条目是可重建的派生索引，不另存一份可能与正文冲突的副本。每次查询重新核对来源内容与阶段确认版本。修改由正式文档提取的条目时，请打开来源文档审阅；手工条目支持编辑和版本递增。

本批数据按需求轮次隔离，不自动合并其他轮次或跨项目经验。检索采用编号和字面全文匹配，不调用模型、不使用向量数据库。

## 稳定编号与来源文件

| 类型 | 来源文件 | 含义 |
| --- | --- | --- |
| FR / NFR / AC | 需求分析阶段.md | 功能/非功能需求与验收标准 |
| ADR | 产品实现设计文档.md | 方案选择、备选、理由和适用范围 |
| TASK | 实现交接.md | 实现任务及其需求/决策引用 |
| TC | 测试案例.md | 可执行的测试用例 |
| EV | 测试结果.md | 命令、结果和代码版本等证据记录 |

使用独立标题、列表项或表格行定义编号；正文引用其他编号会建立有向关联。普通叙述中的提及和代码围栏里的示例不会单独创建条目。编号在本轮内唯一，重复编号与未定义引用会显示为待核对项。

```markdown
### FR-001 登录
用户可以通过已有凭证登录。

### AC-001 正常登录验收
关联 FR-001。使用合法凭证后能进入主页。
```

设计文档中：

```markdown
### ADR-001 使用服务端会话
关联 FR-001 和 AC-001。
选择：使用服务端会话。
理由：需要统一失效和审计。
备选：浏览器持有无状态令牌。
```

测试结果中：

```markdown
### EV-001 登录测试记录
关联 TC-001 和 AC-001。
命令：npm test -- login
结果：未执行
代码版本：填写实际提交或工作区版本
```

知识库不会执行命令，也不会根据「预计通过」推断测试已通过。EV 的结果是文档或用户录入的记录值；未给出明确结果时为 `unknown`。阶段启动提示词已加入上述格式要求，已有无编号文档不会被插件擅自改写。

## 关联与缺口

默认从引用生成：需求 → AC、相关需求/AC → ADR、需求/ADR/AC → TASK、AC → TC → EV。详情中也可手工建立或移除关联。由原文生成的关联需修改原文引用。

检查项包括：功能需求缺少验收标准、验收标准缺少可达证据、设计决策未确认、证据缺少命令或明确结果，以及重复编号/失效引用。有关联不代表测试通过；仍需核对证据的来源、状态和结果。

## 确认状态

- 文档条目的「已确认」要求所属阶段当前仍已确认，且正文哈希与确认快照相符。
- 来源变化会退回草稿并显示需复核；不会沿用过期确认。
- 手工条目的状态由保存时的用户选择决定。
- 废弃条目默认不进入上下文；正式文档中对应的原文段落也会从自动附加正文中移除，并留下说明。
- 参考资料只读取用户指定的本项目 Markdown/文本路径；内容变化后退回草稿。已经选用的参考资料发生变化时，需要重新核对并选用。已废弃资料保持排除。

## 上下文组织

默认选用本阶段工作稿、前序已确认文档、已确认手工知识/参考资料。前序未确认或失效资料、后续阶段草稿与废弃资料默认排除。用户可以在当前阶段保存自己的选择。

每次工作台的阶段启动、继续、修改、修复、部署指令、团队队列启动以及紧凑阶段入口发送任务前，都通过 Host 构建清单。构建失败会停止发送，不悄悄退回只有交接摘要的提示词。原生聊天中直接输入的普通消息不经过此封装。

清单包含：来源路径与哈希、草稿/确认状态、结构化知识和关联、全文/节选/仅引用/排除标记、警告、选用配置版本，以及实际附加的上下文正文。每条实际记录独立保存；资料更新后可以查看旧记录，页面会指出输入已发生变化。

字符预算为 4000–60000，默认 24000，仅约束自动附加上下文，不包含阶段工作指令或已有聊天历史，也不是精确 Token 预算。超出预算会明确记录节选或未注入正文。资料内容作为引文数据提供，不构成新的任务指令。选择策略组织 Agent 输入，不替代文件系统权限控制。

## 接口

| 接口 | 用途 |
| --- | --- |
| GET /workbench/knowledge?q=&type=&status= | 本轮知识、来源、关联、缺口与检索结果；最多返回 100 条匹配知识 |
| POST /workbench/knowledge | upsert / deprecate / restore / link / unlink / reference / selection；必须携带当前 revision |
| GET /workbench/context?stage=spec | 当前阶段的上下文预览、选用配置与最近实际记录信息 |
| POST /workbench/context | `{action:"build",stage:"spec"}` 构建不可变记录；校验前序阶段确认 |
| GET /workbench/context?id=<uuid> | 读取指定实际记录并核对正文哈希 |

接口沿用登录/来源校验、项目目录和看板标识；知识写入冲突返回 409。无效路径、跨看板上下文编号和不匹配的来源版本会被拒绝。JSON 解析失败会显示错误，不覆盖成空知识库。

## 验证范围

53 项自动化测试覆盖前两批功能及第三批的提取、关联、来源变化、搜索、编辑冲突、参考资料、废弃段落排除、上下文预算和历史记录，以及发送失败/看板切换时停止发送。

浏览器在隔离临时项目中使用真实前端组件和 Host 路由，验证了录入、检索、来源跳转、资料选择、启动后记录及实际发送内容，并检查桌面与窄屏。未连接模型，也未改动用户正在运行的项目数据。
