# 第二轮管家改进需求记录

状态：**用户已于2026-11-17明确启动；八项已完成本地实现，待真实模型与线上灰度验收**。原始记录日期：2026-11-17。

用户已发出“根据修改清单开始新一轮修改”。以下保留最初需求表述；本地实现、验证与已知边界以[本轮实现说明](manager-round-two-implementation.md)为准。开发验证时未部署、未推送，未发起真实模型调用；后续 Git 提交和推送不代表线上已部署。

## 1. 登录后的退出入口

反馈：用户登录后看不到退出或注销按钮。

待实现：在独立前端提供清楚可见的退出登录入口，结束当前登录会话并返回登录页。用户原文的“注销”先按退出登录记录；删除账号、项目或数据属于另一种操作，不能把两者混为同一个按钮，是否需要销户待启动后确认。

## 2. 切换项目清空对话输入

反馈：切换项目后输入框仍保留上一个项目的内容。

待实现：切换项目时清空当前对话输入，避免把上个项目的需求发到新项目。启动后同时检查附件、待发送状态及异步返回是否串到其他项目；问题答案和授权状态仍须绑定各自原任务，不能因切换页面而错误提交或批准。

## 3. 修改现有项目的文件夹选择

反馈：新建项目后选择“修改现有项目”，无法选择已有文件夹。

待实现：贯通该入口与文件夹选择、内容预览及导入流程，让用户能明确选择自己已有的项目。启动后核对浏览器目录选择与当前项目资料导入能力；清楚区分“上传参考副本”和“获得可修改的工作区”，不能把上传说成已经直接打开或修改用户本机文件。保留文件清单、敏感文件过滤及明确导入授权。

## 4. 确认问题改为集中选项交互

反馈：管家连续要求多次确认，输入负担重。

待实现：将同一轮相关问题集中呈现，每题提供容易理解的推荐或备选项，并提供“补充说明 / 自己填写”入口，允许自由反馈。一次提交整组答案，避免一题一次打断；支持合适的单选、多选和已答回显，不替用户作未经表达的决定。“一次提供选项”不等于把技术问卷全部堆给用户，问题数量与默认推荐策略在启动后设计。

## 5. 输入区切换为授权确认

反馈：授权操作与普通聊天脱节。

待实现：需要授权时，原对话输入区展示待授权操作与作用范围，原发送按钮切换为“允许授权”或同等明确按钮；同时保留拒绝/取消入口。只批准当前明确操作，展示任务归属，不自动授权。提交中防重复，过期、撤销、失败、停止或切换项目时正确恢复输入区，不把普通聊天内容当作许可。

## 6. 需求分析 Agent 减少澄清负担

反馈：需求阶段要求过多用户确认；用户可能没有需求文档，只有初步想法。

待实现：启动后调研 GitHub 上优秀需求管理/需求澄清 Agent 的实际架构与代码，并记录具体来源及适用性，再优化 DSH 插件的需求分析 Agent 与管家衔接。支持从初步想法形成对应领域的完整需求方案：目标、用户、使用场景、核心流程、功能范围、约束、验收标准及阶段建议。

设计方向待验证：先复述目标并提出可编辑方案，能合理推断的采用明确标记的默认假设，只集中追问会显著改变范围或风险的关键问题；允许用户选择推荐方案并补充。区分用户事实、推断与待确认项，不编造调研、法规、业务数据或测试结论。方案完整不等于自动批准执行，需求确认与工具授权继续分开。

## 7. 输入框支持上下拉伸调整高度

反馈：输入框不能拓展，输入内容较多时可见文字过少，只能上下滚动，阅读和编辑不便。

待实现：为对话输入框提供清楚可见的上下拖动手柄，让用户能够主动扩大或缩小输入区高度，便于查看和编辑长内容。设置合理的最小、最大高度，避免遮住发送/授权按钮或使对话区无法使用；达到最大高度后仍支持内部滚动。拖动不应丢失草稿或触发发送，输入区进入授权确认后布局仍应稳定。启动后核对桌面拖动、窄屏与触屏的可用方式，并提供可访问的替代调整方式。

## 8. 网络访问与回答来源标注

反馈：管家运行任务时无法访问网页、GitHub 或下载依赖。当前执行容器在 `services/worker-bridge/lib/isolation.mjs` 中使用 `--network=none`，模型网关可联网不代表任务工具具有网络访问能力。

待实现：新增受控网络访问，支持检索和读取公开网页、查看 GitHub 项目与文档，以及按项目需要下载依赖。启动后设计网页检索/抓取服务和执行环境的受控出站通道，明确访问范围、下载限制、超时、失败提示与必要授权；不直接把所有容器改成无限制联网，不开放服务器内网、云元数据或将凭据带入任务容器。具体架构与依赖源策略在启动后确定。

回答来源：管家使用外部资料时，在回答末尾提供“内容来源 / 参考资料”，展示实际读取的网页标题、GitHub 仓库或文档名称及可点击的原始链接；重要结论与对应来源建立引用关系。使用项目内资料时标注可定位的文件及适用版本；模型推断、推荐方案和未经验证的假设明确区分，不伪造来源，也不把未读取的搜索结果当作已核实证据。无可用来源或访问失败时如实说明，不声称已经联网核实。来源记录随对话保存，并遵守项目归属和资料访问权限。

验收方向：公开网页与 GitHub 访问、受限依赖下载、拒绝内网目标、超时与断网恢复、引用链接与实际抓取内容一致，以及历史回答仍可查看来源；不得因联网失败自动重复付费模型调用。
