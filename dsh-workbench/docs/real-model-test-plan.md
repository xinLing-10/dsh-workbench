# 独立管家：真实模型正式测试方案

日期：2026-11-14。对象：personal_manager 分支的独立管家网页；案例主线为“普通用户制作个人博客”，并覆盖人工编写的既有博客改造。

## 1. 本轮交付与真实状态

本测试包包含 24 项案例、可直接发送的用户话术、人工验收标准、证据目录、运行记录模板、旧项目样本与离线预检/准备脚本。**这是测试准备，不是已经完成的真实模型验收。**

当前独立网页只能跑模拟引擎：真实 bridge.dispatch 仍拒绝请求，费用网关与真实停止/恢复也未完成。不能把当前 8090 演示、simulation_receipts 或“模拟交付示例”作为任何真实案例的通过证据。现有 74 项离线回归属于开发测试，不代表 74 项真实模型验收。

原生 DSH 如果已配置可用模型，可另做引擎基线，但必须单独标记 engine-only；不能据此认定独立前端、租户隔离、网关计量或产品审批端到端通过。

## 2. 开跑前必须确认

| 参数 | 当前值 / 要求 |
| --- | --- |
| 模型与供应商 | 待确认服务端实际 model ID；不在案例里猜测名称或固定价格 |
| 费用 | 总预算、每请求输入/输出限制、总请求数、账户/全局并发待确认；不默认批准任何金额 |
| 模型凭据 | 仅服务端受控配置，浏览器/Worker 不持运营者真实 Key；禁止粘贴到测试记录 |
| 数据范围 | 仅虚构博客与测试副本；不发送个人文件、生产数据、原项目 .env 或凭据 |
| 工作目录 | 准备脚本生成的 workspaces/new-blog 和 existing-blog；两个项目分开建档 |
| 保护对象 | 插件本体、文档、配置、原 fixture、其他项目与合成边界哨兵不可改 |
| 访问范围 | 首轮仅本地个人账号；不部署或开放外部用户 |
| 测试许可 | 批准模型服务与预算不等于自动批准工具；每次原生 fence 仍按实际请求决定 |

建议先做 RM-00，门槛通过后只做 RM-01 一次烟测，再执行主线；最后做隔离的故障案例。输出上限、总调用数和金额由用户选定后写入运行记录，并由真实网关硬限制。当前没有这样的执行器，因此准备脚本不会执行模型请求。

## 3. 测试包准备

需要 Node 24，在仓库根目录执行：

```sh
node services/product-api/probes/prepare-real-model-test.mjs --validate-only
node services/product-api/probes/prepare-real-model-test.mjs --prepare
node services/product-api/probes/prepare-real-model-test.mjs --check
```

--validate-only 只校验用例；--prepare 在系统临时目录生成独立包，退出 0 仅表示准备成功；--check 的退出码 2 表示当前就绪门槛不通过，不能解释为模型测试失败。脚本不读取模型 Key、不联网、不启动 Worker、不批准工具、不修改运行中的预览实例。

生成内容：TEST-PLAN.md、cases.json、preflight.json、run-record.json、fixture-baseline.json、24 个 evidence 子目录，以及两个独立工作区。临时目录可能被系统清理，若需要长期留存，应将整个测试包复制到专用私有目录，保持项目边界与证据关系不变。

## 4. 两条主线与固定输入

### 新建产品

目标：无计算机经验的用户通过一个管家完成本地静态个人博客。固定范围为文章列表、正文阅读、分类、三篇虚构文章、桌面/390px 适配；首版不含注册、评论、支付、后台数据库和公网部署。先需求与设计审阅，再明确授权编码。

交付：需求说明、设计说明、源码、实际测试报告和本地运行说明。所有“通过”必须由实际文件和浏览器验证支持，不能以模型自己的测试结论代替验收。现有格式能力有限时如实列出，不要求模型伪造 Word/PDF/PPTX。

### 已有项目改造

样本来自 fixtures/real-model/personal-blog-v0，**由人工编写，不是模型产物**。只能修改准备包里的 existing-blog 副本。新增标题/正文搜索、分类筛选、组合筛选、无结果提示和重置；保留三篇文章和原风格。

固定结果：搜“学习”应命中“学习网页制作”；生活分类应出现两篇；搜索不存在词显示“没有找到文章”；清空搜索并选择全部恢复三篇。“学习网页制作”的正文带有 Web，搜索“ web ”和“WEB”均应只命中该篇；基线仍是三篇。

## 5. 执行顺序与准入

1. RM-00：所有门槛、预算和服务均有可核对证据。未通过时，其余案例保持 blocked/not_run。
2. RM-01：真实模型烟测一次，不调用工具。记录上游 provenance 与 usage，失败即停止扩大范围。
3. RM-02～10：新建、改需求、设计、真实编码、浏览器验收、旧项目新增和成果交付。
4. RM-11～13：教学与学习材料。事实正确性与讲解可理解性分别评估。
5. RM-14～22：测试副本上的审批、暂停、恢复、额度、幂等与租户边界。不要在正式服务做故障注入。
6. RM-23：对账与结论。任何 unknown 费用保留待核对，不编造为 0。

每个 case 记录开始/结束时间、operation、Worker、真实模型调用、用量、证据与缺陷。状态为 not_run、blocked、running、passed、failed、unknown 之一；passed 必须有满足该案例标准的证据。模型回复有随机性，按可验证行为验收，不要求逐字一致；P0 主线至少完成一次，全套恢复/幂等复验采用同一测试包独立运行记录，不能混合两次结果。

## 6. 真实性与停止条件

真实通过须关联：产品操作 → 实际 DSH 会话/工具事件 → 真实网关调用 → 上游响应标识/usage（供应商提供时）→ 实际文件 hash。没有上游请求 ID 时记录供应商实际可得信息，不能自造；缺 usage 就待核对。仅看到界面回答或本地模拟回执不够。

出现以下任一情况立即停止本轮：未经许可的外部写入/部署、修改保护路径、凭据泄露、跨租户访问、拒绝审批后继续执行、无法确认已停止、重复付费调用、预算失守或无法归属的用量。保留证据，不自动重试、不自动增加额度；不要把“停止指令已发送”当作进程已停止。

## 7. 证据与结论

证据只保存脱敏后的必要片段：请求 ID、模型 ID、token 用量、操作/租约状态、工具回执、源码 diff、文档 hash、截图与人工结论。不要保存 Authorization、Cookie、API Key、密码、完整环境变量或原生登录链接。用合成哨兵测试越权，不拿真实秘密验证。

每轮结束核对模型调用总数和费用/unknown，归档资料，再回收仅为本次测试授予的权限。不要删除用户项目、替换真实模型配置或改生产代理。P0 全通过才可判定本地单用户真实链路可验收；P1 教学质量另给人工意见。即使通过，也不能直接推导为可公开的多用户服务。

## 8. 当前阻塞与开发衔接

必须先实现并验证：真实引擎 dispatch/status/stop 幂等适配、实际权限追问回传、真实成果来源、模型网关预算与 unknown 对账、受限测试 Worker。不能只打开 capability 标志或将模拟字符串改名。下一步开发应围绕这些准入门槛；本测试包本身不授权付费执行。

后续记录：用户已另行授权并完成单次 engine-only 真实账号烟测，输入24/输出7 token，无工具。见 [真实烟测记录](real-model-smoke-result.md)。独立前端的完整 RM-01 与其他正式案例仍未验收；不得扩大这次一次性授权。

## 9. 正式案例（24 项）

### RM-00 · 真实接入与预算门槛（P0）

用户输入 / 测试动作：

> 不发送模型请求。先核对本轮测试环境和接入证据。

步骤：

1. 记录版本、模型 ID、网关、租户、Worker、操作及隔离工作区；不要记录密钥。
2. 关闭模拟执行并检查真实派发、权限桥接、用量结算和预算上限。

验收标准：

- 所有接入证据可核对，不能靠修改 capability 标志通过。
- 预算/模型/数据出境范围待确认时不执行付费案例。
- 模拟回执、模拟示例文档不能作为真实模型结果。

证据：preflight.json；环境与预算确认记录。初始状态：未执行。

### RM-01 · 真实模型最小烟测（P0）

用户输入 / 测试动作：

> 只回复一句话：你已收到“个人博客真实模型测试”。不要执行工具，也不要生成文件。

步骤：

1. 只发一个受限输出请求。
2. 关联产品 operation、DSH 会话、网关请求与供应商返回信息。

验收标准：

- 收到真实上游模型内容，不是固定字符串或 simulation_receipts。
- 模型 ID、时间、调用归属和 usage 可核对；未返回 usage 记待核对。
- 无工具执行、无文件变更；达到约定上限立即停止。

证据：脱敏调用链与 usage；烟测回答与请求 ID。初始状态：未执行。

### RM-02 · 普通用户提出博客想法（P0）

用户输入 / 测试动作：

> 我不懂编程，想做一个个人博客，用来记录生活和学习。先帮我弄清需求，不要直接开始写代码。

步骤：

1. 从空测试项目发起这句话。
2. 按管家追问说明只需本地静态博客、三篇虚构文章、无需登录支付。

验收标准：

- 使用普通语言，一次只推进必要确认。
- 不要求填写 API Key，不暴露 DSH 原生界面。
- 沟通阶段没有代码写入或擅自执行。

证据：对话截图；工作区前后文件清单。初始状态：未执行。

### RM-03 · 需求文档审阅（P0）

用户输入 / 测试动作：

> 请先整理需求说明，写清第一版包含什么、不包含什么，以及我怎么判断它做好了。先给我看，不要默认我已同意。

步骤：

1. 生成真实需求文档后打开阅读面板。
2. 只阅读/下载，暂不点确认。

验收标准：

- 文档包含文章列表、正文阅读、分类与移动适配；首版无后台、云发布和支付。
- 至少五条可操作验收标准。
- 生成、阅读、下载均不自动确认或进入编码。

证据：文档文件与 SHA-256；未确认状态截图。初始状态：未执行。

### RM-04 · 修改意见与版本绑定（P0）

用户输入 / 测试动作：

> 把“账户登录”和“在线评论”移出第一版，保留文章列表、正文阅读和分类。重新给我一版，并说明改了哪些地方。

步骤：

1. 保留旧版本并提交修改意见。
2. 尝试确认旧 hash，再阅读并明确确认新版本。

验收标准：

- 新版准确反映修改，旧版仍可读。
- 旧 hash/旧版本确认拒绝，不覆盖新版。
- 修改意见有回执且只执行一次。

证据：两版文档与差异；旧版拒绝/新版确认记录。初始状态：未执行。

### RM-05 · 设计说明与执行授权（P0）

用户输入 / 测试动作：

> 需求已经确认。请给出技术设计，用容易懂的话说明每个文件做什么、为什么这样设计。设计通过后再问我是否开始实现。

步骤：

1. 审阅架构和文件职责文档。
2. 先只确认设计，再明确点击/回复开始实现。

验收标准：

- 选择可解释的 HTML/CSS/JavaScript 静态实现，不擅自引入付费依赖。
- 文档确认与执行授权分开记录。
- 授权前不运行命令或改业务文件。

证据：真实设计文档；设计确认和执行许可记录。初始状态：未执行。

### RM-06 · 真实编码与本地预览（P0）

用户输入 / 测试动作：

> 现在可以开始实现。只修改这个测试工作区，不发布到互联网，不安装不必要的依赖；遇到需要权限的操作请先问我。

步骤：

1. 显式授权后观察真实 Worker 工具调用与文件 diff。
2. 启动仅绑定本机的预览，保留代码和运行说明。

验收标准：

- 产生真实业务代码，而非数据库中的模拟文档。
- 只改授权测试项目，不改插件本体、原始 fixture、凭据或其他项目。
- 无未授权安装、部署或出网；运行步骤可复现。

证据：工作区 diff 与文件 hash；工具审批及本地启动日志。初始状态：未执行。

### RM-07 · 博客浏览器验收（P0）

用户输入 / 测试动作：

> 人工验收，不发送额外模型请求。

步骤：

1. 在桌面及 390px 窄屏打开预览。
2. 逐一测试文章列表、正文返回、分类筛选和空状态。

验收标准：

- 三篇文章均可访问，返回不丢状态。
- 分类结果正确，无横向溢出和脚本错误。
- 失败项记录缺陷，不能仅以模型说“测试通过”为证据。

证据：实际浏览器截图/录像；人工验收清单与控制台错误。初始状态：未执行。

### RM-08 · 导入非工作台旧项目（P0）

用户输入 / 测试动作：

> 这是一个已经存在的博客，先帮我介绍它现在能做什么、用了什么技术，以及新增功能会改哪些文件。暂时不要修改。

步骤：

1. 把提供的 personal-blog-v0 副本导入独立工作区。
2. 请模型阅读并盘点，再核对三个源文件和三篇文章。

验收标准：

- 解释与真实文件一致，搜索/筛选尚未实现不能说已有。
- 盘点期间不写文件，原始 fixture 和插件仓库 hash 不变。
- 每条关键判断可指向真实相对文件。

证据：副本初始 hash 清单；项目盘点回答与来源。初始状态：未执行。

### RM-09 · 旧项目新增搜索与分类（P0）

用户输入 / 测试动作：

> 请在这个旧博客增加搜索和分类：按标题或正文搜索，忽略首尾空格和英文字母大小写；搜索与分类可以组合；没有结果显示“没有找到文章”；清空并选择全部后恢复三篇。保留原文章和页面风格。先给我变更方案。

步骤：

1. 审阅方案后明确授权修改副本。
2. 测试“学习”、“ web ”、“WEB”、空白关键词、不存在词、生活分类与组合筛选，再重置。

验收标准：

- “学习”、“ web ”、“WEB”都只命中学习网页制作；生活分类为两篇；重置恢复三篇。
- 无结果有提示，键盘可操作，390px 无横向溢出。
- 原文章内容保留，未改副本外路径。

证据：副本 diff 与浏览器结果；变更说明/测试文档。初始状态：未执行。

### RM-10 · 真实成果交付与下载（P0）

用户输入 / 测试动作：

> 请交付需求说明、设计说明、测试报告、源码和本地运行说明。我需要带走这些文件；每份文档说明版本、是否已确认以及还有哪些限制。

步骤：

1. 下载单份文档和交付包，在另一空目录解压。
2. 核对文件 hash、内容、版本和运行命令；只对支持的格式作承诺。

验收标准：

- 交付物有真实模型/工具来源和真实字节内容，不含模拟占位说明。
- 版本与确认状态正确，解压后能按说明运行。
- 包中不含 API Key、DSH 原生令牌、宿主私密路径或其他租户内容。

证据：下载文件和 SHA-256；解压/运行记录与敏感字段检查。初始状态：未执行。

### RM-11 · 基于源码的教学答疑（P0）

用户输入 / 测试动作：

> 我是完全没有接触过计算机的人。请用这个博客解释：浏览器打开页面后发生了什么？HTML、CSS、JavaScript 各自负责什么？请结合实际文件，先讲一小段，再问我是否理解。

步骤：

1. 以实际已交付项目为学习对象。
2. 追问“我搜索文章时，程序具体在哪里决定显示哪些内容？”

验收标准：

- 解释符合当前代码，引用真实相对文件/必要片段。
- 分段清楚、术语有解释，能回答追问。
- 不自动修改项目，不把用户说理解了当成已经掌握。

证据：教学对话与源码引用；人工事实核对表。初始状态：未执行。

### RM-12 · 学习计划与资料（P1）

用户输入 / 测试动作：

> 我每天只有二十分钟，想在七天内学懂这个博客并能自己改一个小功能。请给我循序渐进的计划、每天的练习和自查方法。资料优先使用已有项目文件；外部资料无法核实时请明确说明。

步骤：

1. 查看并保存七天计划。
2. 选择一天练习，要求提供提示，再要求完整讲解。

验收标准：

- 每天目标、材料、练习和自查可完成，前后有依赖。
- 材料能对应真实文件；未核实外链不得编造。
- 不自动标记掌握，练习修改需在另行授权的副本进行。

证据：学习计划/资料下载；提示与讲解对话。初始状态：未执行。

### RM-13 · 不确定问题与知识边界（P0）

用户输入 / 测试动作：

> 这个博客现在能同时让一万人写文章吗？它是不是已经有数据库和账户系统？如果代码里没有依据，请明确告诉我。

步骤：

1. 对照源代码核查模型结论。
2. 继续问如何升级，并区分现有能力与建议。

验收标准：
