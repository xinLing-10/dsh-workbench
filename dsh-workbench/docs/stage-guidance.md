# 阶段引导、任务队列与执行边界（1.6.1）

## 使用入口

工作区上方的“当前需求与下一步”显示需求名称、当前阶段和操作建议。当前阶段按第一个尚未确认的阶段计算，与正在浏览的文档阶段分开。

- 查看其他阶段时，点击“返回当前阶段”。
- 前序成果已确认时，点击“开始下一阶段”。任务只在点击后发出，不因查看页面自动启动。
- 当前阶段已启动后，可“继续完善本阶段”，或“审阅并确认”打开设置与版本确认。文档缺失、未解决评论、实现检查清单和版本变化仍按既有规则阻止确认。
- 正在运行时提供队列入口；“已启动”仅代表曾经发起任务，不推断会话仍在运行，也不代表成果已确认。
- 全部阶段确认后显示完成提示。

阶段栏同时显示“未开始／已启动／待确认／已确认”等文字。确认成果后仍需明确点击下一阶段的开始入口。同一角色自动接续其他需求改为默认关闭，需用户主动开启，避免确认后意外跳到另一项需求。

## 需求名称与队列

需求名称沿用项目设置中的名称；未填写时用目标首行，再退到“未命名需求 · 第 N 轮”，不把随机任务 ID 当作主要标题。Agent 会话在每次工作台发送任务时同步为“需求名称 · 阶段”。任务提示要求 todo_write 等内部清单以“需求名称 · 具体工作”命名；现有模型任务清单不会为改名而自动重放执行。

点击“团队与任务队列”，每个角色可以展开完整排期，再展开单项需求，查看：

- 需求名称、说明和实际阶段、已确认进度。
- 待开始、已启动、需要重新审阅、等待前序确认等状态。
- 开始时间、内部任务 ID、会话 ID。
- “查看这项需求”：定位指定需求，而非始终定位队首。
- “查看 Agent 会话与任务”：打开对应 DSH 原生会话，查看其任务清单、执行轨迹与工具审批；没有会话时禁用。
- “开始这项任务”：仅对前序已确认且未启动的项开放，不能跳阶段。

队列详情是工作台需求排期；DSH 会话内的 todo 列表通过原生会话查看，两者不混为一套状态。队列在项目、看板或保存版本变化时重新读取，也可手动刷新。旧看板列表会从实际状态补齐名称、阶段和会话详情。

## 插件本体保护原则

工作台发起的业务 Agent 任务只允许修改选定业务项目及本轮交付文档，不得修改工作台插件本体代码、文档和配置。遇到插件问题，只报告问题，不能把修复插件作为业务需求执行。

执行保护包括：

1. Host 在生成执行上下文前检查真实路径，拒绝插件目录、其子目录，以及包含插件的父目录；符号链接别名同样检查。保护范围包含开发仓库中的插件、角色配置和仓库文档。需要开发业务项目时，应选择独立目录。
2. 每份版本化任务上下文保存目标根目录、插件保护目录及禁止间接改写的规则；保护信息包含在上下文哈希中，随阶段启动、修改、修复和部署请求发送。
3. 五个角色的常驻指令包含相同边界，覆盖会话后续讨论；会话创建不能在失败时丢弃目标 cwd、回退到任意默认目录。

上述目录启动检查由 Host 强制执行，任务内的行为要求由角色指令和 DSH 的工具权限共同约束，不应将提示词等同于操作系统级文件隔离。绕过工作台手工创建的其他会话不属于此启动检查的覆盖范围。维护插件本身应使用独立的开发流程，不能通过业务 Agent 任务扩大写入范围。

## 验证范围

65 项自动测试通过，新增覆盖：实际阶段与浏览阶段分离、任务命名、队列顺序及上游等待、真实状态摘要、插件目录／父子目录／符号链接拒绝，以及 Host 在创建看板前拒绝受保护任务。

隔离浏览器使用真实 React 前端和 Host 路由、模拟会话发送回调，验证下一阶段启动、队列展开、指定需求定位、原生会话入口、上游任务禁用及390px嵌入视口布局。实际发送内容核对了需求名称、目标阶段和插件保护规则；本轮未调用真实模型，不声称验证了模型会逐条遵循 todo 命名或所有任意命令的文件写入行为。

更新后需重启 DSH Host 并刷新页面，使 Host 检查及角色 preset 一并加载。未更改 personal_manager 分支或其 stash。

## 需求档案多选删除

需求档案增加逐项勾选、全选、已选数量、取消选择和删除选中记录。删除前通过工作台内的确认面板列出全部待删除需求；取消后保留选择。全选范围是当前列表，按项目目录与看板 ID 精确删除，不影响之后新增的记录。

仅移除档案记录，项目代码、文档、看板和会话保留；看板后续保存可能重新生成档案记录。

本次累计 72 项自动测试通过，覆盖跨项目批量删除、同项目多轮、旧记录空 ID、非法请求整体拒绝、全选快照及并发更新。隔离浏览器验证多选、半选、取消保留选择、确认后刷新、全选清空和空列表禁用按钮；删除后 27 个项目文件的哈希均未变化。

## 对话需求标签

工作台右侧对话标题下显示“当前需求：需求名称 · 第 N 轮”，与当前看板及其阶段对话同步切换；名称沿用需求名称的既有回退规则。标签支持长名称换行和悬停查看，角色标签与完整对话入口保留。未创建会话时也显示当前选定需求，便于识别接下来将处理的对象。这里的轮次是需求看板轮次，不是聊天消息数量。
