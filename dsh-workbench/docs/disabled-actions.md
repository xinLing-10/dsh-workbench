# 禁用功能的启用条件提示（1.14.1）

本轮清点 `client.js` 中全部带禁用条件的操作按钮，共 **80 处定义**。任务队列、问题选项、评论和历史版本等由循环生成，实际按钮数量会随项目数据变化。

| 功能区域 | 定义数 | 主要禁用场景及提示方向 |
| --- | ---: | --- |
| 管家沟通、问题回答与成果确认 | 13 | 目标或消息为空、服务未连接、任务处理中或状态待核对、未勾选审阅确认、未填写修改要求、正在停止任务 |
| 模板与文件交付 | 6 | 当前操作未完成、模板已确认、模板未确认、阶段文档未确认、未检查来源、缺口未补齐、映射变化后未重新检查 |
| 五个阶段的操作与确认 | 20 | 上传或操作进行中、缺少会话、检查项未填写或未完成、未勾选审阅、当前版本已经确认、部署信息或授权不完整 |
| 阶段任务引导与 Agent 队列 | 8 | 操作进行中、前序阶段未确认、没有当前任务、任务已开始、没有会话 |
| 项目设置与需求列表 | 7 | 项目名称或路径为空、路径未变化、文件夹已失效、缺少会话、列表未就绪、未选择需求、删除进行中 |
| 文档、审阅、版本、预览与修改要求 | 10 | 原稿或文档未选择、下载或生成进行中、段落超限、没有未解决评论、评论为空或引用版本过期、修改要求为空 |
| 知识管理与上下文 | 9 | 保存处理中、上下文未调整、保存或关联操作未完成 |
| 工作区、侧栏、对话抽屉与删除确认 | 7 | 任务运行中、缺少会话、前序阶段锁定、删除操作进行中 |
| **合计** | **80** | 每一处均配置明确的启用条件提示 |

## 交互行为

- 点击禁用按钮只显示 toast，阻止原点击回调、表单提交及事件向上冒泡；业务权限与服务端校验保持不变。
- 按钮保持禁用的视觉状态和 `aria-disabled` 语义，同时允许键盘聚焦。鼠标点击以及 Enter / Space 触发同一提示逻辑。
- 多条件按钮按当前状态给出最先需要完成的步骤。例如生成交付件依次检查：处理中 → 模板确认 → 文档确认 → 来源预检 → 补齐缺口或重新检查。
- 悬停提示与点击 toast 使用同一文案。重复点击会重新计时；页面卸载会移除提示订阅并清理计时器。
- 管家服务未连接时，问题选项和回答按钮一并禁用，并提示重启 Host，避免点击后才得到执行服务错误。

本次范围是功能按钮；文本输入、选择器和复选框仍使用原生禁用机制。其中需求行复选框补充了删除中的悬停说明。

## 验证

自动回归覆盖禁用按钮不执行回调、不提交表单、重复提示、恢复启用后的行为、自定义样式和无障碍标签，以及 toast 订阅和卸载清理。隔离浏览器验证了模板未确认、预检未完成和管家服务未连接的提示，并核对点击禁用交付按钮没有产出文件。
